# Как запустить AI Ustaz на другом компьютере

Это инструкция именно для вас — чтобы продолжить работу над **этим же** проектом
(с тем же сайтом, базой данных, аккаунтом администратора) на другом компьютере.
Backend (Supabase, база данных, ИИ-ключ) уже настроен и общий для всех
компьютеров — ничего из раздела «Настройка» в README делать заново не нужно.

## Шаг 0. Убедитесь, что папка на месте

Проект лежит в OneDrive (`Рабочий стол\AI-USTAZ`). Если на новом компьютере вы
вошли в тот же аккаунт Microsoft/OneDrive — папка сама появится и скачается.
Проверьте в Проводнике: `OneDrive → Рабочий стол → AI-USTAZ`. Подождите, пока
у всех файлов пропадёт значок «облако» (значит, файл реально скачан на диск).

Если OneDrive не тот же (другой аккаунт) — нужно скопировать папку целиком
(флешка, архив) или подключить проект к GitHub.

## Шаг 1. Установите Node.js

Скачайте и установите с [nodejs.org](https://nodejs.org) (версия LTS).
Проверьте в терминале (PowerShell или cmd):

```bash
node --version
```

Если команда не найдена — закройте и снова откройте терминал (или
перезагрузите компьютер), Node.js прописывается в PATH при установке.

## Шаг 2. Проверьте файл `.env.local`

В папке проекта должен быть файл `.env.local` (рядом с `package.json`) с двумя
строками:

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

Он **не хранится в git**, но раз папка синхронизировалась через OneDrive —
файл должен быть на месте (проверьте в Проводнике, что он виден; если у
Проводника скрыты файлы, начинающиеся с точки, включите отображение скрытых
файлов). Если файла нет — скопируйте `.env.local.example` в `.env.local` и
возьмите значения в Supabase Dashboard → Project Settings → API (**Project
URL** и **anon public key**), либо просто перешлите себе эти две строки с
основного компьютера (это не пароль, а публичный ключ клиента — не страшно
переслать в сообщении себе).

## Шаг 3. Установите зависимости и запустите

В терминале, открытом **в папке проекта**:

```bash
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173` — это и есть сайт. Если порт
занят другим проектом, Vite сам выберет другой порт и покажет его в
терминале.

Если вместо сайта видите экран «Нужна настройка Supabase» — значит,
`.env.local` не подхватился (проверьте шаг 2 и перезапустите `npm run dev`
после изменения файла — Vite не подхватывает `.env.local` на лету).

## Что НЕ нужно делать повторно

- Заново создавать проект Supabase, накатывать миграции, сеять демо-данные.
- Заново получать/вставлять ключ Gemini.
- Настраивать права администратора — они уже выданы по email
  `perizat0396@gmail.com` (см. `supabase/migrations/0004_admin_analytics.sql`).

Всё это — часть общего облачного backend'а, он один на всех компьютеров.

## Если нужно менять backend (миграции, edge-функцию) с нового компьютера

Понадобится Supabase CLI. Через Scoop (Windows):

```bash
powershell -Command "Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned"
```

```bash
irm get.scoop.sh | iex
```

```bash
scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
scoop install supabase
```

Затем войдите и привяжите проект (запросит логин через браузер и пароль от
базы данных, который вы задавали при создании проекта Supabase):

```bash
supabase login
supabase link --project-ref <ID-проекта>
```

`<ID-проекта>` — Reference ID из Supabase (Project Settings → General).

После этого доступны команды из README — `supabase db push`,
`supabase functions deploy generate` и т.д.

## Продолжить работу с Claude Code на новом компьютере

Сама переписка (история этого чата) не переносится — она хранится локально
на компьютере, где велась. Но весь код, миграции и эта инструкция — в
проекте, поэтому в новом чате достаточно открыть эту же папку и написать
что-то вроде «продолжи работу над AI Ustaz, ознакомься с README и этим
файлом» — Claude быстро восстановит контекст по коду.
